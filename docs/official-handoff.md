# 给主办方的复现交付

本仓库记录 VOLO AI 本账号的“攻防测试”对照，提供独立源码、实际上传包、模型输入输出、官方结果与失败边界。
目的在于核查评测与计量机制，不将固定答案的成绩声明为通用 Agent 能力。

每个任务只有一次真实分类调用。当前请求的 `max_tokens=4` 是输出上限；以上请求实际均为一个输出 Token。
模型回复 Counter、dice 或 ticket，选择包中的固定页面，没有生成页面源码。
Token 数、费用和通过率从平台读取，未填写为目标数值。

零调用历史控制也能通过 Counter，但效率为 null。极短分类控制则能得到很大的有限效率。
这说明仅要求存在模型调用，不能证明模型承担了应用生成工作。公开固定题可以缓存答案，这一问题不依赖读取隐藏题。

## 彩蛋与计费边界

用户已取消精确彩蛋效率目标。`1314520` 保留在提交名与审计元数据中。
`max_tokens` 只限制输出上限，提前结束仍可能产生更少 Token。输入 Token、定价、缓存策略和费用舍入也可能影响效率。
当前实测费用显示到六位小数；不能据此自由指定任意 `pass/CNY`，也不应把标记值当成实测指标。

## 复核建议

1. 用 Release 中的冻结包，按正常流程重新上传到测试账号，并使用相同公开任务。
2. 核对模型 trace 中仅有一次标签分类，应用文件来自固定模板；比较官方计费与 trace 用量。
3. 对 Ticket 使用正常评测参数复核浏览器崩溃，并保留浏览器日志和资源数据；当前未确定其原因。
4. 若目标是生成与泛化能力，用冻结提交后的新任务、语义变化与独立验收补充公开练习题；分别披露缓存、路由与生成。
5. 将验收数据、配置和可信评分输出与候选程序隔离。仅加密公开题或仅封公网无法处理固定答案缓存问题。

公开材料已剔除账号凭据、私人聊天截图、私有宿主路径和无关工程。完整原始日志保留在操作方本地，供主办方需要时进一步核对。
